# 第二阶段性能优化：最多五轮

目标：在 0.6.1 已验证的“检查125条、转换114条通过项”9分32秒基础上，先争取约7分钟，再尝试3–4分钟；最多五轮，仍以端到端墙钟减少至少5%才接受。保持全部数据检查、数值/时间语义和图像质量；失败候选撤回，不以删轨迹、缩小图像或放宽缺口规则制造速度。

实验目录：Marvin `/home/user/tianji-optimization-round2-20261011-oFmEbg`。初始 HEAD `62c2f13`；保持同一125条历史集合。中间对照采用通过项中均匀覆盖时段的24条：17,994行、96段视频，新目录每次全新生成；输入列表在各运行 request.json。使用当前专用解释器，通过独立checkout注入候选，未在实验阶段替换生产环境。

## 第1轮：较长视频优先 + 更充分并发——接受

原 prepare 按目录顺序启动视频；末尾几条长轨迹会留下大量空闲worker等待。改为根据输出帧数从大到小安排视频任务，结果仍映射回原录制索引，manifest/统计/episode顺序不变。默认并发公式上限从8调至12，仍使用CPU affinity可用数减2及录制数上限，显式workers可覆盖。不是CPU隔离或保证业务有空闲核。

| 版本 | 24条端到端墙钟 |
|---|---:|
| 0.6.1 基线 | 157.177 s |
| 候选第一次 | 120.794 s |
| 候选复测 | 122.592 s |
| 候选中位 | 121.693 s |

相对同轮基线降低 **22.57%**，超过5%门槛。首次 prepare 从135.703秒降至99.685秒，其中视频阶段91.429秒；check约19秒，收益主要来自视频调度。进程树峰值RSS约5.33GB（基线3.69GB），CPU累计约895秒（基线861秒），以更多并发和少量调度开销换墙钟减少。

26项执行/管线专项测试通过，包含长任务先启动但manifest顺序和统计归属保持原样。两轮24条的全部数值、审计数组、统计、诊断决策、96段H.264编码包及时间戳与基线完全一致。此轮未改编码器或质量参数。默认worker选择变更有机器负载依赖；125条全量目标尚需最终实测，不能只按24条比例宣称达标。

Tailscale中继偶发握手超时后，长实验采用nohup保存独立日志，检查PID和measurement.json确认终态再决定重跑，未将不完整运行算入上述时间。

## 第2轮：复用重复输出帧的RGB/YUV转换——拒绝

候选对每张源图只做一次RGB→YUV420p转换，并在同一源图对应的多个50 Hz输出时刻复用像素。8项实际编码回归通过，包含包字节、解码像素、统计和损坏尾部检查；24条复测输出的17,994行数值、审计、统计、96段视频包及时间戳与第1轮完全一致。

| 版本 | 24条端到端墙钟 |
|---|---:|
| 已接受第1轮中位 | 121.693 s |
| 第2轮第一次 | 122.237 s |
| 第2轮复测 | 116.000 s |
| 第2轮中位 | 119.118 s |

端到端仅降低 **2.12%**，不足5%。CPU累计约810–814秒，虽低于第1轮约895秒，但用户门槛是端到端墙钟，不能用CPU收益替代。因此撤回代码及专项测试，保留隔离实验和本记录，不进入生产版本。后续轮次仍以第1轮为已接受基线。

## 第3轮：有界NVENC编码与严格质量验收——接受

最终配方为 H.264 NVENC、VBR CQ16、p4、HQ、Main、yuv420p、无B帧、GOP=fps；原始尺寸和50 FPS取样保持不变，所有统计仍由编码前原始RGB计算。CQ不是CRF，不能按相同数字认为画质相同。最多12条录制同时编码（48个相机会话），仍受可用CPU和任务数约束。

| 版本/调优 | 24条端到端墙钟 |
|---|---:|
| 已接受第1轮中位，x264 | 121.693 s |
| NVENC CQ12，4 workers | 130.386 s |
| NVENC CQ12，8 workers | 108.163 s |
| NVENC CQ12，12 workers | 101.123 s |
| 最终NVENC CQ16，12 workers，第一次 | 102.872 s |
| 最终配方复测 | 103.921 s |
| 最终配方中位 | 103.396 s |

相对第1轮中位减少 **15.04%**，超过5%门槛。首次check20.07秒、prepare80.11秒；进程树采样CPU约576–578秒（第1轮约895秒），峰值RSS约7.57GB（第1轮约5.33GB）。4/8/12并发和CQ12/16属于同一编码轮次的参数调优，不是额外优化轮次。

真实24条的17,994行、全部数值、审计数组和统计均与软件基线相同。最终配方两次运行的96段H.264包、时间戳亦完全相同。另选24条中的第0和23条、覆盖两天时段及最长样本，共2,271行/9,084相机帧逐帧对照同一原始图像：RGB和YUV整数平方误差每帧均不大于软件CRF18。RGB平均PSNR从40.304升至42.873dB，最小逐帧差值+1.091dB。此证据是两条完整质量样本，不等同于114条逐帧质量证明，也不是无损视频承诺。

**存储代价明确保留：**24条视频从285,857,406字节增至1,113,639,579字节，约3.896倍；CQ12原先约5.077倍，未作为最终配方。通过提高视频体积保住画质，未缩小分辨率或降低帧率。需要更小文件可显式 `prepare --video-encoder libx264`，保留原CRF18/veryfast策略。

`prepare --video-encoder auto` 在独立子进程中只探测一次当前NVENC配方；探测超时、崩溃或不可用时才回退x264。显式h264_nvenc请求失败直接报错；真实编码运行中失败绝不静默改编码器。缓存记录真实encoder/quality，auto只接受已验证的旧/当前x264或当前NVENC配方，显式请求不匹配时要求新目录。旧缓存复用无需GPU。单会话探测不保证任意显卡支持48会话，本轮结论限实际Thor；用户可降低workers或固定x264。

此前lossless探测产生High 4:4:4 Predictive和明显体积膨胀，CQP0在隔离子进程中原生崩溃，均未采用。最终候选本地177项回归通过，3项真实MCAP opt-in测试另由真实批次验收覆盖。完整125条目标仍以之后的全量实测为准。
