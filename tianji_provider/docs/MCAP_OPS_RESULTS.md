# Tianji provider 重构对照结果

基线为实际运行代码的 37 文件快照 `0e9c6ac`，重构实现为 `48118f3`。两套 Python 环境安装同一版本的 LeTools 和相同的依赖；只有重构侧安装 mcap-ops。测试使用两条生成的 6 秒 CDR + H.264 MCAP，视频为 1920×1080 四宫格、30 Hz；输出为 50 Hz，wrench 为 200 Hz。CPU 为 Intel i9-14900K，固定 4 个逻辑 CPU、1 个 provider worker、libx264 软件编码。未使用生产录制。

| 阶段 | 原版（输出帧/秒） | 重构（输出帧/秒） | 配对吞吐变化中位数 | 四组变化范围 |
| --- | ---: | ---: | ---: | ---: |
| 纯数值对齐（已读入内存） | 71,914.02 | 85,225.10 | +18.90% | +16.62% ～ +20.46% |
| 直接 DataSource（含图像统计） | 171.38 | 186.24 | +8.56% | +8.00% ～ +10.55% |
| 完整质检并创建新缓存（含四路编码） | 41.52 | 42.73 | +3.03% | +2.26% ～ +3.89% |

每组两版使用同一批输入，先后顺序 AB/BA 交替。表中两列吞吐分别取各自中位数，百分比对每组先算新/旧吞吐之比再取中位数。四组范围是观测波动，不是置信区间。数值对齐在内存中重复十次；另外两项每次从 MCAP 读取，使用暖文件缓存且没有重用已生成的转换缓存。

原版 248 项、重构 254 项测试全部通过，含直接 MCAP 到 LeRobot v2.1、v3.0 导出及深度验证。计时前核对两条录制共 468 个标准帧、468 个 DAgger 标注帧、288 个专家分段帧。检查项包括 Arrow 表列类型/缓冲区、运动裁剪后的绝对时刻、每侧原始 wrench 时间、视频包索引、各维统计，以及新缓存四路视频的解码 RGB 像素；上述对照全部相等。测量前后也核对了输入文件的 SHA-256。

这组结果仅代表上述 x86、软件编码、合成双录制负载。未测 Marvin ARM、NVENC、真实长录制、多 worker 或生产存储。代码分支不改变在线数采转换服务。
